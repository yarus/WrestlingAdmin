# WrestlingAdmin

Windows-приложение для подготовки и проведения турниров по вольной борьбе: от регистрации участников и жеребьёвки до управления схватками, синхронизации ковров и итоговых протоколов.

Интерфейс построен на WPF и Material Design. Доступны русский и английский языки; язык и тема сохраняются локально на компьютере оператора.

## Возможности

- Регистрация команд и спортсменов, учёт взвешивания и оплаты, распределение по возрастным и весовым категориям, кеш команд и участников.
- Круговые сетки, подгруппы с выходом в олимпийскую стадию, олимпийские сетки с матчем за третье место или утешением от финалистов. Обычная схема выбора: менее 6 участников — круговая, 6–7 — подгруппы, от 8 — олимпийская с утешением.
- Посев с учётом клуба, города и спортивного разряда.
- Расписание нескольких ковров, перенос категорий между коврами и разделение турнира на последовательные части.
- Управление счётом, таймерами и результатами схваток, отдельное окно табло.
- Автоматическая синхронизация локальных копий турнира между компьютерами в одной сети.
- Каналы слайдов с сетками, ближайшими схватками, изображениями и видео; отдельные окна показа.
- Личные и командные результаты, специальные награды, печать и массовый экспорт PDF.
- Атомарное сохранение `.wrt`, резервные копии, проверка записанного файла и аварийное восстановление.

## Сборка и запуск

Нужны Windows x64 и .NET 10 SDK. Решение — `Wrestling.sln`; приложение использует `net10.0-windows`, библиотеки — `net10.0` или `net10.0-windows`.

```powershell
dotnet restore Wrestling.sln
dotnet build Wrestling.sln
dotnet build Wrestling.sln -c Release
dotnet test Wrestling.sln
dotnet run --project Wrestling.UI.Material
```

Release-сборка настроена на x64 в `.csproj`; платформа решения остаётся `AnyCPU`. Дополнительный параметр `-p:Platform=x64` не требуется.

## Работа с турниром

Навигация разделена на этапы: **Положение → Регистрация → Жеребьёвка → Расписание → Проведение → Итоги**. Настройки и закрытие турнира доступны в общей панели навигации. После открытия файла приложение выбирает этап по состоянию турнира.

При создании турнира приложение предлагает сразу выбрать путь сохранения. Автосохранение выполняется после утверждения или отмены результата схватки и после применения изменений от другого компьютера. Для регистрации, жеребьёвки и правок расписания используйте общую кнопку сохранения. Без выбранного пути фоновое автосохранение пропускается.

PDF-экспорт находится на соответствующих этапах: протоколы взвешивания — в регистрации, жеребьёвки — в жеребьёвке, расписания ковров — в расписании, сетки с результатами — в итогах.

При экспорте протоколов хода поединков на странице «Расписание» можно выбрать нужную часть или все части независимо от активной части ковра и завершения предыдущих. Для всех частей создаются отдельные PDF по каждой паре «ковёр + часть» с непройденными схватками; часть указана в заголовке и имени файла.

### Части турнира

Части позволяют провести несколько последовательных блоков на одних физических коврах, например младшие возраста утром и старшие после награждения. Категория относится к части, а каждый ковёр имеет свою активную часть. Нумерация схваток начинается с 1 отдельно для каждой пары «часть + ковёр». Командные результаты доступны суммарно и с фильтром по части.

При открытии старого файла без частей адаптер создаёт «Часть 1» и связывает с ней категории и ковры. Для раздачи такого файла на несколько компьютеров сначала откройте и сохраните его в актуальной версии на одном компьютере, затем копируйте сохранённый файл: так идентификаторы созданной части будут одинаковыми.

### Синхронизация ковров

Каждый компьютер работает со своей локальной копией одного `.wrt`. Компьютеры обнаруживают друг друга через UDP; при различии хешей состояния приложение загружает файл соседа через встроенный HTTP-сервер и объединяет изменения по версиям. Отдельной страницы «Импорт» и настройки списка сетевых файлов в текущем интерфейсе нет.

- Создайте и сохраните турнир на одном компьютере, затем раздайте копии этого файла остальным операторам. Для отдельного нового турнира используйте «Новый турнир»: переименование файла сохраняет прежний ID.
- На странице «Проведение» в карточке **«Этот компьютер»** проверьте имя и состояние подключения. Первоначально используется имя компьютера Windows; его можно изменить. Имя сохраняется только на этом ПК, отдельно от `.wrt` и папки программы, поэтому при копировании программы/турнира через флешку чужое имя не переносится.
- IP и порты определяются автоматически и не сохраняются. Для обнаружения выбирается свободный UDP-порт из `24565–24569`; объявления отправляются на весь диапазон. HTTP использует `24566` или свободный порт Windows, если стандартный занят. При нескольких сетях объявляется адрес соответствующего интерфейса. После смены сети адреса обновляются автоматически.
- В карточке видны текущие сети, число соседей и причина недоступности обмена; в подробностях — фактические порты, адреса и действие «Повторить подключение». Если заняты все порты обнаружения, работа с турниром и ручной импорт остаются доступны. Брандмауэр должен разрешать входящие подключения приложению в используемой сети. Для работы обнаружения через диапазон используйте одну обновлённую сборку на всех компьютерах.
- Статусы соседних компьютеров доступны на этапе «Проведение». Совместные правки одной сущности нужно согласовывать: при равных версиях остаётся локальное состояние.

Для резервного обмена без запущенного приложения на другом компьютере используйте **«Проведение» → «Импорт из файла…»** в блоке соседних компьютеров. Выберите `.wrt` с флешки, локального диска или сетевой папки (`\\компьютер\папка\турнир.wrt`). Применяются те же правила слияния, что и при автоматической синхронизации: более новые результаты, регистрации, сетки и поля расписания; конфликтующие категории остаются без изменений, независимые изменения принимаются. Результат импорта, число изменений, конфликты и состояние сохранения показываются всплывающим уведомлением.

Если импорт содержит принимаемые изменения, перед ручным слиянием создаётся отдельная копия текущих данных из памяти, включая несохранённые правки, в `%LocalAppData%/WrestlingAdmin/Backups/ManualImports/<ID турнира>/`. Если новых изменений нет, резервная копия и повторная запись рабочего файла не выполняются. Для импорта с изменениями копия создаётся и при отключённых обычных резервных копиях; если сохранить её не удалось, ручной импорт не применяется. При первом импорте ещё не сохранённого турнира приложение предложит выбрать рабочий файл. Исходный файл импорта не изменяется, принятые изменения сохраняются в рабочий турнир.

### Файлы и ресурсы

`.wrt` — JSON-файл с данными турнира. Изображения и звуки задаются путями, поэтому при переносе нужно отдельно переносить используемые ресурсы и проверять пути. Относительные имена командных эмблем и печати/подписи разрешаются через папку `Images` приложения.

Перед перезаписью существующего файла по умолчанию создаётся копия в `Backups/<имя файла без расширения>/` рядом с турниром; сохраняются последние 20 копий. Папку, число копий и включение резервирования можно изменить в настройках турнира. Сохранённое в старом турнире число копий сохраняет силу. Атомарная запись и проверка сохранённого файла действуют и при отключённых резервных копиях.

Кеш команд и спортсменов, журналы и аварийные копии находятся в `%LocalAppData%/WrestlingAdmin/`. Обычные резервные копии перед сохранением и аварийные копии — разные механизмы.

## Код и документация

| Проект | Назначение |
|---|---|
| `Wrestling.Entities` | Доменные сущности, сетки, посев, расчёт результатов |
| `Wrestling.Data` | DTO для сериализации (`*Info`) |
| `Wrestling.DataAccess` | Чтение, запись и резервирование файлов |
| `Wrestling.Providers` | Сервисы, адаптер сущностей и DTO, сеть |
| `Wrestling.UI.Utils` | MVVM-примитивы, DI-контейнер, локализация и утилиты WPF |
| `Wrestling.UI.Material` | Приложение WPF, представления, модели представлений и сборка зависимостей |

Тесты xUnit находятся в `tests/`: доменная логика, провайдеры, файловое хранилище и UI-логика. UI-тесты требуют Windows. Актуальные зависимости указаны в `.csproj`.
